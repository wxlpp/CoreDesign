# Task: 四个图表 + 退化输入契约 + 登记表侧改动

## Description

落 `CoreDesignCharts` 的 4 个图表——**Swift Charts 原生画不出来的那四类**：
`RadarChart`（雷达图）/ `RingChart`（活动环）/ `ActivityHeatmap`（贡献热力图）/
`NetworkGraph`（力导向网络图）。

⚠️ ShipSwift 另外 5 个图表（Line / Bar / Area / Donut / Scatter）全部 `import Charts`，
是 Swift Charts 换皮，**明确不做**。

## Acceptance Criteria

### 第一个 checkpoint（写任何图表代码之前）
- [ ] **验证 `AXChartDescriptorRepresentable` 可在不 `import Charts` 的前提下使用**
      ——它属 Accessibility 框架而非 Charts 框架，但**必须实测**，避免四个图表都写完
      才发现要返工

### 组件
- [ ] 4 个图表可用，数据入参**泛型 + `Identifiable`**，不绑定具体模型类型
- [ ] **不引入 `import Charts`**
- [ ] 全部走 CoreDesign 语义色 token 或调用方传入色，`EffectsColorLiteralGuard` 零违规
- [ ] **US-4 图表 a11y**：4 个各有 accessibility 表示
      （`AXChartDescriptorRepresentable` 或逐数据点 `accessibilityElement` + `accessibilityValue`），有测试
- [ ] `NetworkGraph` **丢弃上游 4973 行 demo 数据**（`SWNetworkGraphData.swift`），
      只落布局算法与渲染

### 退化输入契约（FR-19，图表最常见的 crash 源）
- [ ] **9 类退化输入 100% 有测试，实际 ≥ 15 条**（"空数组 / 单点"两类对四个图表各一条）：
      - 空数组 ×4；单点数据 ×4
      - `RadarChart`：所有轴值相等（归一化除零）、轴数 < 3
      - `RingChart`：total = 0
      - `ActivityHeatmap`：日期区间为空、全零值
      - `NetworkGraph`：零边、所有节点初始位置重合（力导向除零 → NaN）
- [ ] 全部**不 crash、不产生 NaN**

### 规模上限（FR-20）
- [ ] `NetworkGraph` 声明**实测的建议节点上限**（力导向布局通常每帧 O(n²)）
- [ ] **超限行为固定为「截断 + 降级静态布局 + 文档标注」**，有测试
      ⚠️ **不得** `precondition` / `fatalError`——库代码对数据规模抛断言就是让宿主 App crash

### 登记表侧改动（⚠️ 仅当 AD-4 裁定 Charts 走 b）
- [ ] `ComponentRegistryGuard` 扫描根多 target 化
- [ ] 4 条登记写入 `docs/component-registry.json`，走完整判定法
      （可复用 `shipswift-foundation` task 001 样本的 notes 与步骤 2 业界举证）
- [ ] `ComponentRegistryGuard.swift:449` 的 `coredesign == 47` 改 **51**
- [ ] `readmeIndexReconcilesWithRegistry` 联动处理
- [ ] **`ComponentTextParamGuard` 一并接**：4 个图表的 `textParams`（轴标题默认值属 UI 文案）
      会改变 `ComponentTextParamGuard.swift:236-241` 硬断言的 `== 31`；
      **且 FR-7 的边界必须显式编码**——「调用方传入的数据文案（`NetworkGraph` 节点名 /
      `ActivityHeatmap` 日期标签 / `RadarChart` 轴名）**是内容不是 UI 文案**」，
      不编码这条边界会误伤这些数据入参的类型签名
- [ ] **顺带扩 `ComponentJudgeSources.scan` 的根**（它为了 `== 31` 本来就要扩），
      让 task 007 的 reachable-type 验收能引用扩根后的扫描结果
