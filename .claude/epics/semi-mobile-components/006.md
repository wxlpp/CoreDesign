# Task: PinCode 验证码输入

## Description

`Binding<String>` 驱动的验证码 / PIN 分格输入组件，固定格数。`isSecure` 掩码显示可配置，默认关闭（明文展示）。iOS 端使用 `.textContentType(.oneTimeCode)` + `.keyboardType(.numberPad)`，以 `#if os(iOS)` 包裹；macOS 端走等价 `TextField`（无 `keyboardType`）。输入填满触发回调。承接 NFR-2（双端单一实现），不留单端公开符号。

## Acceptance Criteria

- [ ] `PinCode` 为 public 类型，public init，接收 `Binding<String>` 驱动输入值，固定格数（如 `length: Int`）
- [ ] `isSecure: Bool` 掩码显示可配置，默认 `false`（明文展示）；开启后各格以圆点/星号替代实际字符
- [ ] iOS 端使用 `.textContentType(.oneTimeCode)` + `.keyboardType(.numberPad)`，以 `#if os(iOS)` 包裹；macOS 端使用等价 `TextField`（不含 `keyboardType`，该 API 在 macOS 不存在）
- [ ] 不产生单端公开符号：公开 API（类型 / init / 参数）在两端一致，平台差异全部封装在实现内部的 `#if os(iOS)` 分支中（承接 NFR-2）

## Technical Details

- 文件落点：`Sources/CoreDesign/Components/PinCode/PinCode.swift`
- 格子渲染：`length` 个独立格子（各自带边框的容器），`Binding<String>` 按下标分发字符到各格显示（`isSecure` 时以圆点/星号替代）
- 输入机制：可用单一隐藏 `TextField` 捕获系统键盘输入再按下标渲染到各格（常见 OTP 实现手法），或每格各自 `TextField` + `FocusState` 自动前后跳转——两种方式均可，但必须保证两端行为一致
- 平台分支示例：
  ```swift
  #if os(iOS)
  .textContentType(.oneTimeCode)
  .keyboardType(.numberPad)
  #endif
  ```
  macOS 分支复用同一个 `TextField`，仅跳过以上两个 modifier；不额外定义 iOS-only 或 macOS-only 的公开类型/参数
- 值变化时过滤非数字字符（PIN/OTP 场景），并 clamp 长度不超过 `length`；达到 `length` 时触发 `onComplete?(value)`
- 当前焦点格边框颜色走 `.tint`
