# Task: Phase 0 — 共享地基先行

## Description

`semi-mobile-components` epic 的前置任务，落地 Phase 1（10 组件并行 Issue）启动前必须就绪的共享地基，消除并行阶段对单一共享文件的抢改冲突。本任务合入 `epic/semi-mobile-components` 后，Phase 1 各并行 Issue 才能开始。

涵盖四项工作（对应 epic Implementation Strategy Phase 0）：

1. **建集成分支**：基于 `main` 创建 `epic/semi-mobile-components` 分支并推送到远端（只建分支，不建共享 worktree——每个 Issue 后续各自经 `using-git-worktrees` 基于此分支开私有 worktree）。
2. **占位/连线取色定案**：占位底色复用 `FillColors`（systemFill 家族），连线/分隔复用 `BorderColors`/separator；shimmer 高亮**优先从 `FillColors` 派生**（`Color.mix(with:by:)` / `.opacity()`，承 accent 衍生态先例），力求不新增 colorset。**Contingency**：若定案后确需新 colorset，本任务需一并补上 `swift package clean`（macOS SwiftPM 以目录形式分发 `.xcassets`，增量构建不拷贝新增 colorset 目录，资源缺失是静默失败）以及在 `Tests/CoreDesignTests/ColorAssetGuardTests.swift` 登记新 asset。
3. **`Localizable.strings`(+`.stringsdict`) 预登记**：枚举 Phase 1 全部新交互组件（Rating / PinCode / Radio / FloatButton / Steps / TagInput 等）所需的 accessibility label 与复数键，append-only 一次性登进 `Sources/CoreDesign/Resources/en.lproj/Localizable.strings`（及 `.stringsdict`）。登记后，Phase 1 并行 Issue 一律不再改这两个文件；并行期发现漏键则记入对应 Issue、暂用已登记键或英文字面量+TODO，由 013（Phase 3 收尾）统一补登。
4. **`scripts/run-snapshots.sh` 加 `KEEP_LIBRARY_SNAPSHOTS=1` 保留开关**：正确实现是三件套——跳过脚本开头 `rm -rf docs/snapshots`（line 11）、把库内 `CoreDesign_*` 快照产物导出到 scratch 目录（而非 `docs/snapshots`）、跳过 line 26 对 `CoreDesign_*` 的删除行。否则 Phase 1 并行阶段（NFR-5.1）逐 Issue 视觉评审既拿不到截图，又可能污染已提交的 `docs/snapshots`。
