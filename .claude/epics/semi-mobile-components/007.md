# Task: Radio 单选组

## Description

新增单选组组件 `Radio`——`Binding<Selection>` 驱动、支持水平/垂直排列的互斥选择控件。视觉上**与既有 `Components/CheckBox/`（`CheckBoxToggleStyle`）成对**：这是仓库既有的非 HIG 先例（Apple 原生更推荐 macOS 用 `.pickerStyle(.radioGroup)`），Semi 组件集里 Radio 与 CheckBox 是并列的表单控件，为保持跨端视觉一致与既有 CheckBox 语汇延续，本任务**不采用** `.pickerStyle(.radioGroup)`，而是复刻 `CheckBoxToggleStyle` 的 token 用法（`Color.contentPrimary` / `Color.gray`、`CoreControlMetrics.iconSize(for: .regular)`、`CoreSpacing.sm`、44pt 命中区手法），只是把方框换成"圆点"（Semi 风格 radio dot）。

## Technical Details

参考实现落点：`RadioOption` 是纯数据结构（`value`/`title`），`RadioGroup` 内部用 `ForEach(options)` 渲染每行，`onTapGesture { selection = option.value }`。选中判断走 `selection == option.value` 的值相等（`SelectionValue: Hashable`），不引入额外的公开状态枚举。

**测试重点**（Swift Testing，覆盖受控逻辑）：
- `RadioOption.id == value`（Identifiable 契约）
- 一个抽出的纯函数（如 `private static func isSelected(_ option: RadioOption<S>, in selection: S) -> Bool`）在多组输入下的正确性——把选中判断逻辑抽成可单测的纯函数，而不是只能通过渲染验证

**不做的事**：不新增公开的"选中/未选中"状态枚举（沿用 `SelectionValue == self` 布尔判断即可，无需 StatusLevel 一类的语义分类）；不碰 `Localizable.strings`、`TouchTargetTests.swift`、`DynamicTypeLayoutTests.swift`、`Previews.swift`、`ComponentData.swift`——这些留给 013 收尾任务汇入（本任务只在 `#Preview` 里做非正式的 44pt / 大字号观察，供视觉评审参考）。
