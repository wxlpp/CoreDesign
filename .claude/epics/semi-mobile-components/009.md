## Technical Details

参考 `Sources/CoreDesign/Components/Form/Form.swift` 中 `LabeledContent { ... } label: { Label { Text(...) } icon: { LabelIcon(...) } }` 的既有用法作为 `LabeledContent` 调用惯例参照（epic Dependencies 明确列出 `Form.swift` 为 LabeledContent 参照）。

**列布局实现建议**：`Descriptions` 接收的 `content` 是一组 `LabeledContent` 行（`@ViewBuilder`），2 列态下用 `Grid { GridRow { row1; row2 } ... }` 或等价 `LazyVGrid` 两两配对；由于 `content` 是任意 `ViewBuilder` 组合，两两配对需要通过 `Group(subviews:)`（iOS 18+，`InsetGroupedSection` 已用此手法遍历真实子视图）取得行数再切分，而不是要求调用方显式传数组。

**测试重点**（Swift Testing，覆盖受控/格式化逻辑）：
- `DescriptionsColumns` / `DescriptionsDividerDensity` 的枚举值行为（若有从 `dynamicTypeSize` 推导"是否强制单列"的纯函数，对其做参数化测试）
- 若列切分逻辑（奇数行时最后一行占满整行等）抽成了纯函数，覆盖奇偶行数场景

**不做的事**：不在 `InsetGroupedSection` 内重复实现分隔线（直接传 `dividerInset`/依赖其默认分隔逻辑）；不碰 `Localizable.strings`、共享测试 suite、`Previews.swift`、`ComponentData.swift`。
