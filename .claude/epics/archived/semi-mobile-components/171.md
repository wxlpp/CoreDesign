# Task: Carousel 走马灯

## Description

新增 `Carousel` 走马灯组件——**单一跨端实现**：`ScrollView(.horizontal)` + `.scrollTargetBehavior(.paging)` + `scrollPosition(_:)` 驱动分页滚动。**不使用** iOS-only 的 `TabView(.page)`（承 epic NFR-2「双端单一实现，不留单端公开符号」）。功能包含：自动轮播（可关闭，`.task`/异步序列驱动 `scrollPosition`）、页点指示器、手势滑动（原生 `ScrollView` 手势，无需自定义 `DragGesture`）。

## Technical Details

**跨端 API 确认**：`scrollTargetBehavior(.paging)` 与 `scrollPosition(id:)` 均为 `ScrollView`/`List` 通用 API（非 `UIScrollView` 专属包装），在 iOS 与 macOS 上行为一致，这是选择该实现路径而非 `TabView(.page)` 的直接原因（`TabView(.page)` 的 `PageTabViewStyle` 在 macOS 上不可用）。实现前建议用 Context7 拉取 SwiftUI `ScrollView`/`scrollTargetBehavior` 最新文档确认 API 细节（`swiftui-layout-components` skill 或 context7 MCP）。

**自动轮播与用户交互的协调**：可选方案——
1. 用 `.onScrollPhaseChange { _, phase in }`（iOS 18+/macOS 15+ 通用）探测用户是否正在拖拽/减速，写入 `@State private var isUserInteracting: Bool`，`.task` 循环里 tick 前检查该标志，为真则跳过本次推进；
2. 或更简单地：用户滑动一旦触发 `selection` 变化，重置 `.task(id: selection)` 的计时基准（`.task(id:)` 在 `id` 变化时会取消旧 Task 重启新 Task，天然获得"手动滑动后重新计时"的效果）——**优先尝试方案 2**，实现更简单、不依赖新 API 探测。

**测试重点**（Swift Testing，覆盖受控/格式化逻辑）：
- 回绕逻辑抽成纯函数：`static func nextID<ID>(after current: ID?, in ids: [ID]) -> ID?`，覆盖"末尾回绕到首个"“空集合返回 nil”“单元素恒返回自身”等边界
- 页点指示器"第 N / 共 M 页"文案的格式化逻辑（若有）

**不做的事**：不实现纵向走马灯（PRD 未要求）；不碰 `Localizable.strings`（页码用 `FormatStyle` 数字格式化，非固定字面文案）、共享测试 suite、`Previews.swift`、`ComponentData.swift`。
