## Technical Details

### ⚠️ `ComponentTextParamGuard` 不在本 task 处理

它**只能守 B 类**（public init 的裸文本参数），且定义域是**登记表条目**
（`ComponentTextParamGuard.swift:228-242` 按 `repo == "coredesign"` 取 `textParams`
并硬断言 `== 31`）。公约 **G-8** 逐字「FR-4 判据以**登记表条目**为定义域」。

它**守不到** FR-7 要求的 **A 类** chrome 文案——公约 **G-4**（`component-contract.md:1017`）
明载「A 类文案不经任何一路进入 FR-4 的机器视野……评审（无机器判据）」，
**连 CoreDesign 自己都没守住 A 类**。`ChromeTextLiteralGuard` 就是为此新建的。

⇒ `ComponentTextParamGuard` 的**扩展与 FR-7 边界编码归 `shipswift-effects` 的 A-6**
（与 `47→51` 同一处），不在本 task。

⚠️ **上文新增的「47→51 由 task 255 抬」与本行是同一件事，不是两个 owner**
（AD-4 第 3 轮终审 I-12）：以本行为准，A-6 就是 task 255 的一部分。

### ⚠️ `TouchTargetTests` 结构上不适用

`TouchTargetTests.swift:3` 是 `@testable import CoreDesign`、`:57` 整 suite `#if os(iOS)`。
往里加 `BeforeAfterSlider` 会让 `CoreDesignTests` 依赖图含新 target ⇒ **违反 NFR-5②**，
把 task 002 立的那条 `jq` 判据判红。
⇒ 本 task 不动它；两个真交互件（`BeforeAfterSlider` / `GlassOrb`）的触控目标测试
由 Epic A / B 在**各自的独立测试 target** 里同形态实现。

## 后续 / Follow-up（PR #265 终审留痕）

### S-5：两条字面量守卫尚无例外台账

`EffectsColorLiteralGuard` 与 `ChromeTextLiteralGuard` **没有**逐站点的逃生门，
而本仓其余守卫都有带**署名理由**的台账：`docs/bool-exemptions.json`（键 + reason）、
`docs/a11y-exemptions.json`（`location` 精确到行 + `symbol` + `reason`）、
`ComponentExtensionPointGuard.knownMissingExtensionPoints`。

⚠️ **失效形态**：第一个**正当**例外出现时（例如某个动效确实需要一个不随外观变化的
物理常量色），没有台账可写的人最省力的出路是**放宽判据或整条关掉守卫**——正是 G-7
记在案的那条。⇒ 两条守卫的头注释已把这句话写进「已知的口子」段落
（「出现正当例外时应**新增台账**而**不得**放宽判据」），但**台账本身没建**：
建一份新台账属新设计（键的形状、reason 的空话词判据、双向差集、与 `#Preview` 口子的
关系），超出 `#246` 的射程。

⇒ **移交**：由 Epic A（`shipswift-effects`）落第一个真组件时按需新建，形态照
`docs/a11y-exemptions.json`。在那之前，任何「为了让守卫变绿而放宽 `hueNames` /
`textConstructors` / `isProse`」的改动都应当被评审拦下。

### P-1：`.module` 归属曾有两处重复断言（已收敛，但结构仍待定夺）

`GuardScanRootsGuard.moduleBundleOwnership` 与 `AccessibilityStringLiteralGuard`
的 `moduleIsResolvedPerTarget` 曾各自断言一遍「只有 CoreDesign 拥有资源包」。
PR #265 终审 I-4 修复时已收敛为**单一权威**（前者做一致性判据，后者只消费返回值），
但「两处是否该合并成一处」属结构偏好，留给用户定夺。
