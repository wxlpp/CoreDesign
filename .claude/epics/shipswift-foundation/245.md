# Task: 两个新 target 骨架 + CI scheme 切换

## Description

在 `Package.swift` 新增 `CoreDesignEffects` / `CoreDesignCharts` 两个 target 与两个
`.library` product，并**在同一个 commit 内**切换 CI 的 iOS 腿 scheme。

⚠️ **这是整个 epic 里唯一一个会让 CI 变红的 commit**——manifest 与 scheme 必须同步，
详见下方 Technical Details。

probe 调用点、README 索引小节。

## Technical Details

### ⚠️ 切 scheme 不是可选优化，是本 task 的硬前置

**实测事实**：本仓当前 `xcodebuild -list` **只有一个 scheme `CoreDesign`**——单 product
时 Xcode 把包 scheme 合并进去，所以 CI 现在的 `-scheme CoreDesign` 能跑测试。

**新增 product 后**，scheme 列表变成 `CoreDesign` / `CoreDesign-Package` /
`CoreDesignEffects` / …，而 `xcodebuild test -scheme CoreDesign` 会**直接硬红**：

```
error: Scheme CoreDesign is not currently configured for the test action
```

⚠️ **失效形态是硬红，不是静默不跑**（这一点初版描述有误）。
`ci.yml` 现有的 `-skip-testing:CoreDesignTests/ToastHostTests` 在包 scheme 下语法不变。

### 为什么测试 target 必须独立

并入现有 `CoreDesignTests` 需要 `@testable import CoreDesignEffects`，会让
`CoreDesignTests` 的依赖图包含新 target，**与 NFR-5② 直接矛盾**（上面那条 `jq` 判据会红）。
⇒ 独立测试 target 是唯一自洽解。

### ⚠️ worktree 里不要跑 `xcodegen generate`

改完 `App/project.yml` 后**不要在 worktree 里跑 `xcodegen generate`**：会把 local package
的 `name` 按当前目录名（而非 `CoreDesign`）写死，并清空
`xcshareddata/xcschemes/CoreDesignPreview.xcscheme`。完整警告与恢复步骤见
`App/project.yml` 顶部注释；验证要覆盖 `name=` 字段与文件内注释两种形态的目录名残留。
