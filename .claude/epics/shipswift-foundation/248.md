## Technical Details

### 已实测的硬事实（评审阶段已跑过最小 spike，Swift 6.3 / swift-driver 1.148.6）

- **原生 `swift build`** 对 target 内 `.metal` 报
  `warning: found N file(s) which are unhandled`，**不产生 metallib**，
  也**不合成 `Bundle.module`**。声明成 `.process(...)` 资源后只做 `Copying Probe.metal`
  ——**拷贝源码，不编译**。
- `swift build --build-system swiftbuild` 与 `xcodebuild` 才产出
  `.../default.metallib`。

⚠️ **而 CI SwiftPM 腿、`scripts/downstream-probe`、下游 StoryUI 的 CI 用的都是原生构建。**

### α / β 的裁决判据（写死，不留给 spike 自由发挥）

**路径 α（`.metal` 源随 target 编译）**
- 可选条件：**所有已知消费路径都能切到 `--build-system swiftbuild`**
- ⚠️ 该条件**今天已知为假**（`downstream-probe` job 是原生 `swift build`；
  StoryUI CI 是 SwiftPM `swift test`）
- α 的失败形态是**运行时静默无渲染**——最坏的一类
- ⇒ **除非本 spike 证明这些路径都可切，否则不选 α**

**路径 β（预编译 metallib 作二进制资源）—— 默认走向**
- 3 份 metallib + `.copy(...)` + 运行时按 `#if targetEnvironment(simulator)` / `os(macOS)` 选
- `.metal` 源须从 target sources **`exclude:`**（否则 xcodebuild 会另编一份同名产物，
  **冗余**——不是冲突，但运行时加载哪一份不确定）
- `scripts/build-metallib.sh` + **sha256 manifest 守卫**（`metallib.manifest.json` 记每个
  `.metal` 的 sha256 + 工具链版本）
  ⚠️ **同步守卫不得用"重编再比对二进制"**——metallib 产物跨 Xcode 版本不保证逐字节稳定

### β 的四个可预见失败模式（本 task 须一并回答）

1. **工具链耦合**——脚本须钉 `-std=` 与 `-mios-version-min=26.0`，否则新 Xcode 编的
   metallib 在旧运行时上加载失败 = 静默无渲染
2. **Mac Catalyst 误选**——`#if os(macOS)` 在 Catalyst 下为假、又非 simulator ⇒ 会选到
   `iphoneos` 份。package 未声明 Catalyst ⇒ **须明写不支持**
3. **仓库体积**——每次改 shader 最多提交 6MB 二进制，考虑 Git LFS
4. **构建产物冗余**——见上
