闸②裁定可落地 11 **总数**，其中属 `layerEffect` 的只有 **3 个**：

| # | shader | 裁定 | 上游 |
|---|---|---|---|
| 1 | `GlassOrb` | 已追到兼容许可 · **MIT** | Inferno 的 "Warping Loupe"（Paul Hudson） |

### ⚠️ 范围收窄：`Halftone` 只落了两个 `.ts` 中的一个，**待用户确认**（PR #303 终审 I-3）

本表逐字点名 `halftone-dots.ts` **+ `halftone-cmyk.ts`** 两个上游文件，本次只移植 dots。

- **分离在源码层面成立**：`u_noiseTexture` 那条依赖属于 `halftone-cmyk.ts`
  （`:80` 声明 sampler、`:98` 本地定义 `randomRG()`、`:171` 真的调用），
  `halftone-dots.ts` import 的是**程序化**的 `proceduralHash21`，不携带该依赖。
  ⚠️ 该结论核到的是**仓内二手记录**（`docs/shader-provenance.md`《⑤-bis》），
  PR #303 终审无网络、未能一手复读上游。
- **代价已逐条列出**（CMYK 四色分色 + `gooey` / `holes` / `soft` 三种点形 + 六边形网格
  + `inverted` + 对比度 sigmoid + 三档颗粒），**后续建议写在文档里**
  （`docs/shader-provenance.md`《`Halftone` 的落地记录（#283）》）而不只在 PR 正文。
- ⚠️⚠️ **但「任务书点名两个 `.ts`、交付一个」是一次 AC 范围收窄，须用户拍板**，
  与 `GlassOrb` 的 Inferno 许可残余风险**同级** —— 后者已标「待用户确认」，本条同等对待。

## ⚠️ AD-F 的「layerEffect 段难度显著高于 colorEffect」**对本批不成立**

AD-F 的依据是「7 个颜色写死件全是 `layerEffect`」——那 7 个是
`ChromaticGlass` / `Foil` / `Glitter` / `IntenseBling` / `PolishedAluminum`（ShaderKit 5）
+ `GlassLogo` + `LiquidMetal`。**它们没有一个在可落地 11 里**（ShaderKit 5 与
`LiquidMetal` 判 `待追溯`；`GlassLogo` 判 `待追溯` 且已由 #261 以 `GlassSymbol` 之名落地）。
⇒ 本批 3 件**不含**任何「把 `.metal` 里的调色板全部提到 Swift 侧」的改造，
#248 给的 **2–3 小时/个**难件工时**不适用**，按 **1–1.5 小时/个**。

⚠️ 连带：**#248 交付 B 里那 7 个难件的工时估算彻底失去用武之地**，
而 `N_B` = 5 的分母（2.0–2.5h/shader）正是靠「可能落地的集合里有 7 个难件」加权出来的
⇒ **分母偏高** ⇒ `N_B` 偏大 ⇒ 闸②的门槛被高估。#280 的 `N_B` 重估须并入这一条。

## ⚠️ 一处须在开工时确认的分类

`Water` 在 epic 的分类表里属 `layerEffect`（该分类来自 ShipSwift 快照的实现形态），
而它的上游 paper `water.ts` 是**背景**类效果。两者不必然矛盾（ShipSwift 可以把它做成
作用于内容层的形态），但**开工第一件事是读 `SWWater.metal` 的签名确认它到底是
`colorEffect` 还是 `layerEffect`**；若实为 `colorEffect`，成员移到 #282、本 task 剩 2 件。

## Acceptance Criteria

- [ ] 3 个落成 `public struct … : ViewModifier` + `public extension View` 便利方法（AD-E）
      - ⚠️⚠️ **本条已修订，不是"默认通过"**（PR #303 终审 I-3）：实交 **2 个**（`Water` 已由
        #280 改判 `待追溯`、不在可落地名单里），且两个 `ViewModifier` 类型都是 **internal**、
        只公开 `View` 扩展方法。
      - 形态理由：`CoreDesignShaders` 树上两种形态并存 —— `RefractiveGlassModifier` 是
        internal modifier + `public extension View`（**同族先例**），`GlassSymbol` 是
        `public struct: View`（因为它**自带内容**，没有那层渐变背衬折射不成立）。
        本批两件**都不产生内容**、只重采样调用方的内容层 ⇒ 按语义归前者，
        且 `Modifier/` 目录的既有约定逐字要求"以 `View` 扩展形式暴露，而不是要求调用方写
        `.modifier(...)`" —— 把 modifier 类型 public 出去等于承诺那条调用形态永远可用。
      - ⇒ **记为 AC 修订**（数量 3 → 2、可见性 public → internal），不是"AC 已满足"。
- [ ] `.metal` 侧零硬编码色；tint 以参数传入（沿用 #261 的形态——shader 读不到 `.tint`）
- [ ] **必须 `#include <SwiftUI/SwiftUI_Metal.h>`**，否则
      `error: use of undeclared identifier 'SwiftUI'`（#248 ⑤ 实测）
- [ ] **Reduce Motion**：冻结**时间**输入，但**保留手势/倾斜的空间输入**
      （放大镜跟手是交互不是动效）——`GlassOrb` 是这条的主要对象
- [ ] **Reduce Transparency**：`GlassOrb` 降级为不透明形态

      以 `RefractiveGlass` 落地、`ChromaticGlass` 判 `待追溯` ⇒ 本 task 只承接 `GlassOrb`；
      `RefractiveGlass` 那一条归 B-4 复核）
      - ⚠️⚠️ **AC 已偏离，更正痕在此**（PR #303 终审 I-2）：`coreDesignGlassOrb`
        **全程不产生半透明像素**（唯一返回是 `layer.sample(...)`，alpha 原样透传）
        ⇒「降级为不透明形态」在本件上**没有对应的失效面**，照字面兑现是恒真空判据。
        **实交形态**：`softness == 0` ⇒ 圆内常数放大 + 硬边，观感由"玻璃珠"退化成"硬边镜片"，
        放大功能完整保留。行为判据 `RenderProofTests.glassOrbSofteningClosesTheSeam`。
      - ⚠️ 该替代物**在第一版上不成立**：衰减项当时照抄上游 `+= smoothstep(…) * 0.5`，
        那个常数与上游 `zoomFactor: 2` 配套，而本仓三档 1.6 / 2.4 / 4.0 一档都不是 2
